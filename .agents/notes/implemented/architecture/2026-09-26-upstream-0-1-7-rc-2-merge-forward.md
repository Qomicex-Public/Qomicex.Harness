# Agent Note: Upstream 0.1.7-rc.2 merged forward over the fork's 154 commits

Status: implemented

English | [中文](2026-09-26-upstream-0-1-7-rc-2-merge-forward.zh.md)

## Problem

The fork sat on upstream `0.1.7-rc.1` plus 154 local commits while upstream published `0.1.7-rc.2` (344 commits: the Schedule and time-context rows shipped into the Web composition and then disabled by default, timed user-question waits, localized approval explanations, desktop quit confirmation and the Windows tray, the model-selection pending spinner, shortcut editing, account sign-out routing, and 119 fixes). The fork's customizations — the bio-memory system, the JunSi/pentest presets, the Firecrawl default backend, the Qomicex rebrand, permanent session deletion, the bundled dshmarket, YOLO mode, the win32 hidden-console fix, the browser-use/computer-use promotion, and the Windows release packaging — had to survive the merge, and upstream's structural changes had to be adopted.

## Decision

Merge-forward in one merge commit: merge the `dsh-v0.1.7-rc.2` tag onto the local tip. Conflict resolution followed one rule: keep every Qomicex customization, adopt every upstream functional change, and never touch a released session-format edge (`session-format-v2-to-v3` and its validators stay byte-frozen). Of the 82 conflicting files, 13 code and configuration files were hand-resolved; the documentation and i18n pairing records were taken from upstream and then regenerated by the documentation gates against the merged tree; `pnpm-lock.yaml` was regenerated with `pnpm install --lockfile-only` after the manifest merges.

### Where the fork's customizations met upstream's new architecture

- **Promotion absorbed upstream's new files.** Upstream added `locale/en.json` and `locale/zh.json` under the old `packages/experimental/browser-use-*` and `packages/experimental/computer-use-cua-driver-*` directories the fork emptied when it promoted those packages. The locale files moved to the promoted directories (their manifests already declared `./locale/*.json`), and the four empty old directories were removed — leaving them would have made tsdown treat each as a workspace member without a `package.json`, resolving the member's name to `dsh-root` and failing the host build with a missing root entry.
- **The desktop bundle step moved upstream.** rc.2 runs `pnpm --filter @deepseek-ai/dsh-desktop run bundle` from the root `build:lib:host` script, which is what the fork's `tsdown.config.ts` object-form workspace include had provided locally; the array form upstream ships was taken instead.
- **Schedule belongs to the host plane.** rc.2 ships the `schedule` row in the Web composition with `disabled: true`, so the fork's junsi and pentest preset rows were removed: a row belongs to exactly one plane, and the host composition now owns it.
- **The desktop README kept the fork's release section.** Upstream's quit-confirmation, tray, and shortcut documentation was adopted with Qomicex branding, and the fork's GitHub Release pipeline section was restored on both language sides (the merge had dropped it from the Chinese page only).
- **The experimental README kept the promotion.** Upstream's optional-bundle sentence was adopted, but its re-listing of the promoted Cua Driver and browser-use packages was removed: those directories no longer exist under `packages/experimental`.
- **Local package versions aligned.** The 18 fork-only packages now carry `0.1.7-rc.2`.

### Local gaps this merge surfaced

- **`MemoryDedupeValue` was unclassified.** The local commit of 2026-09-26 that added `ctx.memoryController.dedupeMemories` referenced a type the Cordis catalog's type-link policy does not know; it now carries the same memory-controller README exemption as its siblings.
- **Lint adapted to rc.2 types.** The sandbox grant tests wrap their throwing calls in braces, and the memory settings browser spec drops an assertion `as never` that rc.2's widened remote type made unnecessary.

## Consequences

- `SESSION_FORMAT_VERSION` stays 4; committed v3 and v4 generations are untouched.
- Verified: `pnpm run typecheck` (host and client through the full `build:lib` passes), `pnpm run lint`, `pnpm run verify-cordis-config` (204 config files including both preset patches), and `pnpm run doc-sync` green except the documented persistence gate.
- **Known debt, inherited not introduced:** `verify-persistence-changes` fails on the fork's YOLO approval policy value `'always'` breaking the accepted v4 baseline; the failure is the same one recorded for the rc.1 merge-forward.
- **Known pre-existing failures, unchanged by this merge:** `packages/client/ui-settings-general/tests/apply.client.spec.ts` and `shell.client.spec.ts` cannot boot the whole-client roster because the external dshmarket bundle registers through `window.__ModuleLoader__`, which the in-process test assembly does not install. The composition row, the test assembly's import path, and the dshmarket pin are all untouched by this merge; the failure predates it.
- Snapshot replay (`test:snapshot`, `test:web`) cannot run on a Windows host without symlink privilege, as recorded for rc.1.

## Alternatives considered

- **Rebase the 154 commits onto rc.2** — 154 conflict re-resolutions and a rewritten `origin/master`; rejected, as for rc.1.
- **Cherry-pick selected upstream fixes** — leaves the fork structurally divergent from every later upstream release; rejected.

## Verification

`tsc -b tsconfig.host.json` and `tsc -b tsconfig.client.json` exit 0 through `pnpm run build:lib:host` and `pnpm run build:lib:client` (including the desktop bundle step); `pnpm run lint` exits 0; `verify-cordis-config` passes 204 config files; `pnpm run doc-sync` reports 41 passed and 1 failed (the documented persistence gate); the focused vitest run over the affected packages passes 97 of 99 files, with the two dshmarket files failing exactly as before the merge.
