# Agent Note: Desktop 欢迎页入口直嵌 API Key 表单

Status: implemented

[English](2026-09-26-desktop-welcome-entry-key-form.md) | 中文

## 问题

欢迎窗口原先把 DeepSeek 账号登录作为主操作：入口页只有“登录”和“添加 API Key”两个按钮，“稍后配置”的跳过入口藏在密钥表单之后的二级页里。安装用户在跳过或配置密钥之前必须先穿过第二个页面。窗口还带着上游的 `deepseek HARNESS` 品牌资源。

## 决策

入口页现在直接内嵌密钥表单：品牌图、标语、API 密钥输入框，其下依次是**保存并继续**（主按钮）、**稍后配置**（次按钮）和操作行下方的小字**登录**链接。Key 二级页取消；登录状态页保持独立。账号通知不再打断正在输入的密钥——入口页保留草稿；空闲的入口页则跟随通知进入登录状态页。该守卫直接读取输入框 ref，因为账号监听器持有首次渲染的闭包。欢迎窗 grid 从三行（标语、表单、登录页叠放同一行）改为四行，标语与表单不再互相叠压。品牌 SVG 用上一版字稿的鲸鱼路径重新编写，字标改为 `Qomicex HARNESS`，与安装器一致。

## 后果

入口页变高；600 × 700 窗口仍可容纳。`welcomeKeyTitle`、`welcomeKeyDescription`、`welcomeKeyBack` 词典随其服务的页面一并移除，两份 `-api-key` 期望快照并入入口快照。renderer 平面（welcome.css、welcome.html、assets/welcome-brand.svg）为源码直接打包，合并无需改动 bundle 即可抵达发布产物。

## 考虑过的替代方案

- **只调整入口页按钮主次**（Key 为主、跳过为次、登录降级）——密钥输入框仍在二级页后，正是被反馈的问题。
- **保留三个页面、在入口页加跳过按钮**——两处跳过入口，且入口页仍无密钥表单。

## 验证

两个语言的快照重生成合并后的入口（密钥输入框与三个操作依次排列）；22 个 welcome-renderer 用例全部通过，含忙位守卫、非法输入、重试、跳过与草稿保护流程。`tsc -b apps/desktop`、oxlint、桌面套件 1160 个用例与桌面构建（378 kB 自包含 main.js）均通过。换上 fresh renderer 平面的打包副本以新品牌与内嵌表单启动，无叠压。
